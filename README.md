**Every open-weight TTS model under 1B parameters <br> with the applied numbers you need to pick a local model for a voice agent.**

Small open TTS models have crossed a line: several now stream in real time on a CPU, and the under-1B tier is where "runs on my machine" stops being a hope and starts being a spec. This list exists for one reader: a developer choosing a local TTS model for a real application (a LiveKit or Pipecat agent, an offline device, a self-hosted API) who needs the applied numbers, not a research survey.

**What this list is.** A neutral registry. Every open-weight model under 1B parameters gets a row. No rankings, no editor's pick, no "best" column. The table gives you the facts that change the decision; you weigh them for your build.

**What this list is not.** A benchmark we run ourselves. Every number here is compiled from the internet and carries a source link plus a hardware note. Latency numbers are not comparable across rows unless the hardware matches, and the table never pretends otherwise.

### Runtimes that cover many rows at once

Three actively maintained runtimes turn several "DIY" cells above into a supported path. Check these before writing glue:

- [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx) (Apache 2.0): WASM, Android, iOS and Raspberry Pi builds for Kokoro, Piper, MeloTTS, Matcha-TTS, ZipVoice and Pocket TTS.
- [mlx-audio](https://github.com/Blaizzy/mlx-audio) (MIT): the Apple Silicon path for Kokoro, CSM, Kitten, Marvis and others.
- [audio.cpp](https://huggingface.co/audio-cpp/audio.cpp-gguf): a llama.cpp-style GGUF runtime carrying builds of Pocket TTS, Supertonic, Inflect, Irodori, Chatterbox, Kokoro and Magpie.

## Restricted-license models

Rule 3 says licenses are reported, not judged. These models meet every other rule and their weights download today, but the license on the **weights** is non-commercial, copyleft, revenue-capped, absent, or contradicted by the upstream chain. The restriction is stated first because it is the column that decides whether you can ship.

A permissive badge on a GitHub repo does not mean the weights are permissive. On several rows below the code is MIT or Apache 2.0 and the weights are not.

## Contributing

PRs welcome. The bar:

- New model rows: open weights, under 1B strictly (rule 1), active in the last 12 months, all columns filled or marked not published.
- Benchmark numbers: must include a source link, the hardware, and the vendor or community tag. Numbers without provenance are declined in review, whichever direction they point.
- License corrections: highest-priority PRs. Licenses move; a wrong label here does real damage.
- Parameter counts: prefer `safetensors.total` from `https://huggingface.co/api/models/<org>/<name>` over a README claim. Vendor prose has been wrong by 2x and by 5x in models on this list. If you derive a count from file sizes, say so in the cell.
- Removals: models inactive over 12 months move to an Archive section via PR, with the reason noted.

Open an issue first for anything ambiguous, especially boundary parameter counts.

**This file is the only source.** The [filterable site](https://1btts.voicegateway.dev/) is generated from the tables above at build time, so a PR editing README.md is a complete contribution. Do not edit anything under `site/` to add or change a model. Every filter (size, licence class, CPU real-time, streaming, published latency) is derived from the cells you write, which is why the column vocabulary matters: write **not published** rather than leaving a cell blank, and lead the License cell with the licence on the *weights*. To check your edit parses before opening the PR: `cd site && npm install && npm run check`.

## The rules

These are the inclusion and honesty rules. Every PR is checked against them.

1. **Under 1B parameters, strictly, measured on the model checkpoint.** The published parameter count of the released checkpoint must be below 1,000M. **Required codecs, audio tokenizers, and text front ends do not count against the gate**, even when they push the deployable stack over 1B; state the extra weight in the Params cell so the reader knows what they are actually downloading. Where a project ships several checkpoints, the row names the specific one it describes and only sub-1B checkpoints qualify. One boundary exception is grandfathered in: **Sesame CSM-1B sits exactly at 1B and is included as the named boundary case.** Nothing else at or above 1B gets a row.
2. **Open weights you can download today.** A model earns a row only if the weights are publicly downloadable now, not gated behind a waitlist or a demo API. Hugging Face auto-gated repos (instant click-through, no human review) qualify and are marked "HF gated (auto)" in the Integration path column, because CI needs a token for them.
3. **License is reported, not judged.** Non-commercial and restricted-weight models are listed, in [their own table](#restricted-license-models), with the restriction stated plainly. We do not exclude them and we do not bury the restriction in a footnote. The license reported is the one on the **weights**, which is frequently not the one on the code repo.
4. **Every number carries a source and a hardware tag.** Format: value (tag, hardware) with a link. Tags are **vendor** (published by the model's authors) or **community** (measured and published by a third party). A cell with no defensible source says **not published**. An honest gap beats a confident guess. Real-time factor is not time to first byte and must not be reported as one.
5. **Active within the last 12 months.** Repo commits, releases, or maintained forks count. Abandoned models move to the Archive section rather than being deleted, so the history stays useful.
6. **Neutral tone.** Descriptions state what a model does and what it needs. Marketing adjectives are removed in review.

## How to read the table

- **Params** is the model checkpoint. Where a required codec or tokenizer adds significant weight, the cell says so. Counts read from `safetensors.total` are exact; counts marked derived come from file-size arithmetic; counts marked vendor-stated come from prose and have been wrong before.
- **Streaming** tells you whether the model can emit audio before finishing the full utterance, and the mode where known. **Output-streaming** returns chunks but needs full text up front. **Dual-streaming** accepts text token-by-token while emitting audio, which is what hides TTS latency inside LLM generation in an agent.
- **TTFB / first-chunk** is time to first audio. This is the number that governs agent use. It is meaningless without the hardware note attached to it.
- **CPU real-time** is a three-value column: **yes** (community consensus that it runs faster than real time on a modern consumer CPU), **borderline** (real time only with quantization or short utterances), **no** (GPU required for real-time use).
- **Integration path** answers the question most lists skip: is there a maintained LiveKit or Pipecat plugin, a community wrapper, or are you writing the glue yourself. For agent builders this is often the deciding column. A plugin named after a vendor frequently wraps that vendor's **hosted API**, not the open weights; where that is true the cell says so.
